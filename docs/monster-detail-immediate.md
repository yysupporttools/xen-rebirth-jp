# モンスター情報の直接保存

モンスター詳細の「情報を編集」では、Lv・必要DEFの最小/最大・ドロップアイテム・出現場所・備考だけを編集し、その場で公開します。追記の要点・分類・確認用画像は入力不要です。出典と表示名は任意です。画像は既存の「画像を追加」を使います。

- `site-feedback` の `save_details` アクションを使用。登録済みモンスターIDを公式サイトの図鑑データではなく当サイトの `monsters-data.json` と照合します。
- ブラウザーは編集前後を比較し、変えた項目だけを `details` に送ります。省略した項目は変更しません。
- 明示的に空欄へ変更した数値は `null`、文字欄は `""` として保存し、その項目の表示を未登録へ変更します。元の資料と過去の投稿は保持します。
- サーバーがモンスター名・要約文・内部分類 `note` を生成。公開情報には `publication_mode: "immediate_details"` が付きます。
- 数値は整数のみ、Lv 0〜300、DEF 0〜10000。両方を送ったDEFは最小<=最大。既存表示との範囲確認はフォームでも行います。
- 情報保存用の独立カウンターで 10分60件/日本時間1日500件。画像60枚/500枚と通常修正報告5件/30件はそのままです。
- `site_feedback_save_details` は service_role のみ実行可能、SECURITY INVOKER・空の search_path。公開/匿名ロールに新しい書き込み権限を付与しません。
- 確認用受領記録と `monster_updates` の公開行を同一トランザクションで追加。失敗時は両方と利用件数が巻き戻ります。既存のpending投稿を一括公開する処理はありません。
- 一般記事の修正報告と管理者レビューの権限確認は従来どおりです。管理者が直接保存情報を再編集する場合も公開方式マーカーを維持します。

導入SQLは `docs/monster-detail-immediate.sql`。新しいテーブルや既存列、RLS方針の変更は不要です。
